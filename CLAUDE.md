# gameWE CounterStrikeSharp plugin - notes for Claude

C# plugin for [CounterStrikeSharp](https://github.com/roflmuffin/CounterStrikeSharp)
on Counter-Strike 2 (`src/GameWE/`, translations in `lang/*.json`), a port
of the gameWE SourceMod plugin (itself a fork of the gameME plugin). CS2 has
no `LogToGame`, so the plugin **posts its own log lines over HTTP** to the
address the collector set with `logaddress_add_http` (or `LogUrl` in the
config). It executes the collector's replies, which arrive as server
commands over RCON (`gamewe_psay`, `gamewe_msay`, `gamewe_browse`,
`gamewe_raw_message`, ... plus the `gameme_*` aliases). It has no database
access of its own.

Layout:

- `src/GameWE/Core/` - game independent logic (log line format, weapon
  stats, command text parsing, chat colors, player settings store, damage
  tracker, HTTP log sender). No CounterStrikeSharp types here, so the tests
  compile these files directly.
- `src/GameWE/*.cs` - the plugin (`GameWEPlugin` partial class: events,
  server commands, chat, menus, displays), config `GameWEConfig`.
- `tests/GameWE.Tests/` - xUnit tests for `Core/` and the translations.

Build: `make build` (.NET 10 SDK, warnings are errors), `make test`,
`make package`.

Releases: Conventional Commits + semantic-release (`.releaserc.json`). The
GitHub workflow builds and tests every push to `main` (packages as a
workflow artifact only); `feat`/`fix`/breaking commits make semantic-release
write `VERSION` (the project reads it, so the assembly version follows),
write `CHANGELOG.md`, commit `chore(release): vX.Y.Z [skip ci]`, tag
`vX.Y.Z` and publish the GitHub release with the packages. There is no
tag-triggered workflow.

## Documentation layout (the same in all gameWE repos)

- Root: `README.md` (overview, requirements, quick start, documentation
  table, components, building, license), `CHANGELOG.md` (generated),
  `LICENSE`, `CLAUDE.md`.
- `docs/`: `INSTALLATION.md` (install, update, uninstall, troubleshooting),
  `CONFIG.md` (all settings), `USAGE.md` (commands, pages, operation),
  `INTERFACE.md` (log lines, RCON commands, APIs between the components),
  `DEVELOPMENT.md` (build, tests, CI, releases).
- New documentation goes into the matching file there; no other top-level
  doc files and no per-distribution install guides.

## Invariants that must not break

- Collector commands (`gamewe_*`, `gameme_*`) run only when the caller is
  the server (`player == null`: server console / RCON). A player who types
  one in the console gets nothing.
- **The log address is a secret:** its path holds the collector's token.
  It is never written to the server log, the console, the chat, an
  exception message or a log line, and never shown in docs with a real
  value.
- Player-controlled text (name, chat, clan tag) goes into log lines only
  through `LogFormat` (`Sanitize`: `"` becomes `'`, control characters
  removed, length limited), so a name cannot fake an event.
- Player chat triggers (`rank`, `top10`, ...) are only matched against the
  fixed lists in `PlayerCommands.cs` and logged; the plugin never executes
  text from chat or from the collector with `Server.ExecuteCommand` or a
  client command.
- `Server.ExecuteCommand` only with fixed command names; values in it
  (the log address) are checked with `CommandText.IsLogUrl` (no `;`, `"`,
  spaces, newlines).
- User ids from commands are resolved with `Utilities.GetPlayerFromUserid`
  and checked (`IsValid`, connected) before use; lists of ids are bounded
  (`CommandText.MaxRecipients`).
- Text for the center HTML panel always goes through `ChatText.Html`
  (HTML-encoded), so names and collector text cannot inject markup.
- URLs shown to players (`gamewe_browse`) and the log URL accept only
  `http(s)://`.
- The plugin runs on the game thread: no blocking I/O there. The HTTP
  sender and the settings file write run off the game thread and never
  touch CounterStrikeSharp objects; the HTTP queue and every collection
  fed by players are bounded.
- The settings file (`addons/counterstrikesharp/data/GameWE/players.json`)
  holds only SteamID64 keys and the display settings, no names or
  addresses; its path is fixed.
